# Event Booking System — MVP Consultation Questions

> **Phase:** Phase 1 — Requirements Gathering  
> **Goal:** Agree on a small, realistic Minimum Viable Product (MVP) to build in Phase 2.
>
> **How to use this document:** Start with the main questions. Ask follow-ups only when an answer leaves an important decision unclear. Record the client's answers; do not treat suggestions or assumptions as confirmed requirements.

## What the project brief tells us

The brief points toward an Event Booking System for concerts and special events. The customer-facing experience includes:

- A homepage featuring upcoming events and featured artists.
- Event listings and a calendar for discovering events.
- Event detail pages.
- A customer profile or personal-information area.
- A VIP guide or special-access packages, with ideas such as celebrity meet-and-greets.
- A request for the team to think creatively about the VIP experience and identify features that may be unnecessary.

The brief does **not** clearly specify the exact booking process, payment method, ticket delivery, account rules, or event-management tools. These are open questions, not confirmed requirements.

---

## 1. MVP Goal and Scope

**Main question:**  
What is the most important thing the first version of this system must let a customer do?

**Follow-ups, if needed:**
- Which features from the brief are essential for the first version: event discovery, event details, booking, customer profile, VIP information, or something else?
- Are there any features we should deliberately leave out of the MVP and consider only in a later version?
- How will you decide that the MVP is successful?

**Decision to record:** The agreed MVP features and the features explicitly deferred.

## 2. Event Discovery and Details

The brief mentions upcoming events, featured artists, event listings, a calendar, and event details.

**Main question:**  
What is the simplest way customers should be able to find an event and decide whether they want to book it?

**Follow-ups, if needed:**
- Do customers need both an event list and a calendar in the MVP, or would one be enough initially?
- What information must appear on an event detail page—for example, date, venue, description, artist, ticket options, or availability?
- Do customers need search or filters in the MVP, or is browsing a list of events sufficient?

**Decision to record:** The event-discovery features and minimum information shown for each event.

## 3. Standard Booking Flow

**Main question:**  
After a customer chooses an event, what steps should they follow for the booking to count as complete?

**Follow-ups, if needed:**
- Should customers book on our website, or should the site direct them to an external booking or ticketing service?
- Do customers need to choose a ticket type or quantity?
- Does the customer need to pay during booking, or is the MVP only expected to record a booking or booking request?
- What should the customer see at the end—for example, a confirmation message, booking reference, or ticket?

**Decision to record:** The start and end of the MVP booking flow, including what “booking complete” means.

## 4. Accounts and Customer Profile

The brief indicates a customer profile or personal-information area, but it does not define account behavior.

**Main question:**  
What should customers be able to do in their profile in the MVP?

**Follow-ups, if needed:**
- Must customers register or log in to book, or can they book as guests?
- Is viewing and updating personal information enough, or should the profile also show booking history and tickets?
- If guest booking is allowed, how should customers retrieve their booking details afterward?

**Decision to record:** Whether accounts are required and the minimum profile features.

## 5. VIP Guide and Special Packages

The brief highlights VIP experiences and asks the team to propose ideas, particularly around special access such as celebrity meet-and-greets. The exact VIP process is not specified.

**Main question:**  
What should a customer be able to do with VIP packages in the MVP?

**Follow-ups, if needed:**
- Is the VIP section mainly an informational guide, or should customers be able to book or purchase a VIP package through the system?
- Are VIP packages tied to specific events, or are they presented as a separate offering?
- What is the one VIP benefit or experience you most want the MVP to communicate or support?
- Should VIP booking follow the same process as standard tickets, or a different one?

**Decision to record:** Whether VIP is informational, bookable, or purchasable in the MVP, and the minimum VIP journey.

## 6. Payments and Tickets — Only If Included in the MVP

The brief does not confirm online payment or digital-ticket requirements. First establish whether they belong in the first version.

**Main question:**  
Does the MVP need to handle payment and ticket issuance itself, or is that handled outside the system?

**Follow-ups, if needed:**
- If payment is included, which payment method or provider is required?
- If tickets are included, should they be digital tickets, a booking reference, or another format?
- At what point should the system mark a booking as confirmed?

**Decision to record:** Whether payments and ticket issuance are in scope, and the minimum expected behavior.

## 7. Who Maintains Events and Bookings?

The brief mainly describes the customer-facing experience; it does not clearly define the management side.

**Main question:**  
Who will add and update events, ticket availability, and VIP package information?

**Follow-ups, if needed:**
- Does the MVP need an admin or staff area to manage these details?
- If no management area is needed initially, how will event information be supplied and updated during the MVP?

**Decision to record:** Who maintains event information and whether an admin interface is required for the first version.

## 8. Final MVP Check

**Main question:**  
Can we confirm the smallest set of features that must work for the MVP to be considered complete?

Review the answers and confirm:

- [ ] Customers can discover and view event details.
- [ ] The agreed standard booking flow has a clear outcome.
- [ ] The customer profile is included only to the agreed extent.
- [ ] The VIP experience is included only to the agreed extent.
- [ ] Payments and ticket issuance are explicitly included or excluded.
- [ ] Someone has a defined way to maintain event information.
- [ ] Features deferred to a later version are documented.

These checklist items are prompts for agreement, not pre-approved requirements.
